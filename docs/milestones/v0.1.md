# OpsPilot v0.1：故障分析 CLI

> 本版本是[项目总纲与路线图](../project-roadmap.md)中的第一个可复查工程基线。它的目标是先完成稳定调用、进程内会话、usage、脱敏记录和验收闭环，不提前实现 RAG、Agent 或产品化工作台。

## 目标

用 Go 建立最小但完整的模型调用骨架，让用户可以输入 Go HTTP 服务的故障现象，获得初步分析，并在同一会话中继续补充信息。

## 非目标

- 不接入 RAG、Runbook 和历史事故库。
- 不实现 Agent 自主循环和 MCP Server。
- 不自动查询或修改生产系统。
- 不在本阶段完成重试、限流、熔断和完整可观测性。
- 不把模型生成的诊断当作有证据的事实。

## 验收场景

1. 输入“Go 服务请求延迟突然升高”，得到初步分析。
2. 补充“数据库连接池等待时间上升”，模型能结合前文继续分析。
3. 使用流式模式输出，并在中途取消一次请求。
4. 模拟服务端错误，CLI 输出可理解错误且会话仍可继续。
5. 查看 usage 和会话记录，确认没有保存密钥或未脱敏敏感信息。
