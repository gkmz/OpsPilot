# M1-P03：usage、会话和 v0.1 验收

## 目标

在 P02 的进程内多轮流式诊断基础上，补齐模型调用的 usage 记录、会话安全保存、错误分类和 v0.1 最终验收，使一次诊断运行具备可复查的工程证据。

## 当前基线

- `internal/llm` 已支持非流式和流式 Chat Completions 调用。
- `internal/app` 已支持命令行初始问题、后续交互输入和上下文取消。
- `internal/conversation` 当前只在内存中保存 `system`、`user` 和完整 `assistant` 消息。
- P02 已有本地假服务、竞态测试、静态检查和实践证据。

## 必须完成

### 1. usage 记录

- 记录输入 Token、输出 Token 和总 Token。
- Provider 返回 usage 时保存准确数值。
- Provider 不返回 usage 时使用明确的未知状态，不把零值误认为真实统计。
- 多轮请求能够区分每轮 usage 和会话累计 usage。
- 流式和非流式调用的 usage 行为保持一致。

### 2. 会话保存

- 设计经过脱敏的会话记录格式。
- 默认提供安全的本地保存方式，或明确提供关闭保存的选项。
- API Key、Authorization Header 和其他敏感配置不得写入会话记录。
- 会话保存失败时给出可理解错误，不影响内存中的当前结果。
- 记录会话消息、时间、状态和 usage，但不伪造失败请求的完整 assistant 消息。

### 3. 错误分类

至少区分以下错误类别：

- 配置错误：环境变量缺失或格式非法；
- 网络错误：连接失败、超时和底层传输失败；
- HTTP 错误：服务端返回非 2xx；
- 协议错误：响应 JSON、SSE 或 choices 结构非法；
- 取消错误：用户主动取消或上下文截止。

错误应保留底层 cause，便于测试使用 `errors.Is` 或 `errors.As` 判断；CLI 展示信息应包含类别和必要上下文，不泄露密钥。

### 4. v0.1 验收

- 完成核心测试、竞态检测、`go vet` 和构建。
- 在 `docs/evidence/` 保存正常、取消、错误和 usage 证据。
- 复查 README、里程碑、实践笔记和证据之间的描述一致性。
- 完成 v0.1 复盘，记录已实现能力、明确限制和后续版本入口。
- 创建 `v0.1.0` tag 前确认没有未提交的无关文件或敏感信息。

## 明确不做

- 不在本阶段迁移 OpenAI SDK；
- 不实现自动重试、限流、熔断或 Provider 路由；
- 不实现 RAG、Agent、MCP、自动修复和 React 工作台；
- 不把 usage 当作成本结算系统；
- 不保存未经脱敏的完整请求头、环境变量或生产日志；
- 不为了保存失败调试信息而把半截 assistant 写入正常会话历史。

## 推荐会话记录格式

具体字段可以在实现时调整，但应保持以下边界：

```json
{
  "session_id": "session-001",
  "created_at": "2026-08-29T00:00:00Z",
  "messages": [
    {"role": "system", "content": "..."},
    {"role": "user", "content": "..."},
    {"role": "assistant", "content": "..."}
  ],
  "usage": {
    "prompt_tokens": 12,
    "completion_tokens": 34,
    "total_tokens": 46,
    "known": true
  }
}
```

真实实现必须补充文件权限、写入失败、重复保存和敏感信息脱敏策略。示例中的时间和内容仅用于说明字段，不代表真实运行数据。

## 建议实现顺序

1. 先定义错误类型和 usage 聚合模型；
2. 增加单轮和多轮 usage 测试；
3. 定义会话记录结构并实现脱敏；
4. 实现安全保存和关闭保存选项；
5. 将配置、网络、HTTP、协议和取消错误映射到统一类别；
6. 补齐本地假服务和文件保存失败测试；
7. 更新 README、证据和 v0.1 复盘；
8. 完成全量回归后再创建 `v0.1.0` tag。

## 预计影响文件

- `internal/llm/client.go`：统一 usage 和错误边界。
- `internal/llm/client_test.go`：补充 usage 缺失、流式 usage 和错误分类测试。
- `internal/app/run.go`：接入 usage 聚合、会话保存和取消错误处理。
- `internal/app/run_test.go`：补充多轮 usage、保存失败和错误分类测试。
- `internal/conversation/conversation.go`：提供可序列化的会话快照或导出模型。
- `internal/conversation/conversation_test.go`：验证快照、脱敏和失败消息边界。
- `internal/session/`：必要时新增会话记录、脱敏和本地存储模块。
- `internal/errors/`：必要时新增统一错误类别；如果规模很小，也可以保留在 `internal/llm`。
- `cmd/opspilot/main.go`：增加保存位置、关闭保存或 session 相关 CLI 选项。
- `README.md`：补充 usage、会话保存、脱敏和错误说明。
- `docs/evidence/M1-P03-usage-session-acceptance.md`：记录最终验收证据。
- `docs/notes/`：记录 usage、脱敏保存和错误分类的工程实践。
- `docs/milestones/v0.1.md`：完成 P03 清单并记录 v0.1 结论。

- [ ] 多轮会话能够保存每轮 usage 和累计 usage。
- [ ] 会话记录不包含 API Key、Authorization Header 或其他敏感配置。

- [ ] 错误保留底层 cause，CLI 信息可理解且不泄露敏感信息。

## 完成标准

只有当 usage、会话安全保存、错误分类和完整回归都有代码、测试与证据支撑时，才将 P03 标记完成。P03 完成后，v0.1 才具备创建正式版本 tag 的条件。
