# M1-P01：定义 CLI 与项目骨架

## 目标

建立 OpsPilot 的最小可运行骨架：用户提供一段 Go HTTP 服务故障描述，CLI 从配置的 OpenAI 兼容端点发起一次非流式请求，并输出模型返回的初步分析。

本阶段优先固定项目边界、输入输出、配置方式、Prompt 约束和基础错误语义，为后续多轮、流式和会话能力提供稳定基线。

## 已完成范围

- 建立 Go 模块和按职责拆分的目录结构。
- 提供 `cmd/opspilot` CLI 入口。
- 支持从命令行参数或标准输入读取故障描述。
- 通过环境变量配置 Base URL、API Key、模型名称和请求超时。
- 支持可替换的 OpenAI 兼容 `chat/completions` 端点。
- 定义 `system`、`user` 和模型响应消息结构。
- 提供面向 Go HTTP 微服务故障分析的初始 System Prompt。
- 解析模型文本和可选 usage 信息。
- 对配置错误、网络错误、HTTP 错误和协议错误提供明确返回。
- 使用本地 `httptest` 假服务覆盖核心请求和错误路径。

## 当前实现结构

```text
cmd/opspilot/main.go          进程入口和退出码处理
internal/app/run.go           CLI 用例编排和输入读取
internal/config/config.go     环境变量读取与配置校验
internal/diagnosis/prompt.go  故障分析 Prompt 和消息构造
internal/llm/client.go        OpenAI 兼容非流式客户端
```

## 运行方式

运行时必须显式提供模型服务配置：

```bash
export OPSPILOT_BASE_URL="https://provider.example.com/v1"
export OPSPILOT_API_KEY="你的 API Key"
export OPSPILOT_MODEL="当前可用模型名"

go run ./cmd/opspilot "Go 服务请求延迟突然升高"
```

可选配置请求超时，默认值为 `60s`：

```bash
export OPSPILOT_TIMEOUT="30s"
```

也可以通过标准输入提供故障描述：

```bash
printf '%s\n' "Go 服务请求延迟突然升高" | go run ./cmd/opspilot
```

## 已知边界

本阶段只证明单次非流式调用链路可以运行，不证明以下能力：

- 多轮会话和消息历史管理；
- 流式增量输出和中途取消；
- 会话持久化和跨进程恢复；
- 完整的 usage 记录与成本统计；
- 诊断结论的事实正确性；
- RAG、Agent、MCP、自动修复和生产级可靠性治理。

这些能力分别在 `M1-P02`、`M1-P03` 和后续版本中实现。

## 交付说明

P01 完成后，项目具备继续开发 `M1-P02` 的基础。后续实现应保持当前客户端、配置和诊断 Prompt 的职责边界，不在流式需求中提前引入 Provider 路由或生产级治理能力。
