# 课程与项目映射

本文只记录课程知识如何进入 OpsPilot，不承载公开文章正文。

## 三类资产

| 资产     | 保存位置        | 作用                                        |
| -------- | --------------- | ------------------------------------------- |
| 独立实验 | `ai-exp`        | 隔离变量，验证模型、参数、Prompt 或算法结论 |
| 工程实现 | `OpsPilot`      | 保存 Go 代码、测试、ADR、里程碑和可复查证据 |
| 课程文章 | notebook 知识库 | 将理论、真实实践和工程判断整理成可发布文章  |

实验代码不作为 OpsPilot 的生产依赖。进入项目的是实验结论、接口设计、测试样本和验收标准。

## 可追踪标识

每个学习与实践单元使用稳定 ID：

```text
M1-E01  模块一实验：Token 可视化
M1-G01  模块一通用实操：最小 Go 模型客户端
M1-P01  模块一项目：定义 OpsPilot 故障分析 CLI
M1-P02  模块一项目：多轮与流式诊断
M1-P03  模块一项目：usage、会话和 v0.1 验收
```

代码仓库的里程碑、证据记录和知识库文章都使用同一个 ID。文章发布时再补充对应的 Git tag 或 commit。

## 信息的唯一来源

| 信息                       | 唯一来源                             |
| -------------------------- | ------------------------------------ |
| 功能是否实现、测试是否通过 | OpsPilot 代码与测试                  |
| 为什么采用某个设计         | `docs/adr/`                          |
| 某个版本应交付什么         | `docs/milestones/`                   |
| 命令、输出、指标和失败样本 | `docs/evidence/`                     |
| 理论解释、叙事和公开教程   | notebook 课程文章                    |
| 课程整体完成度             | notebook 课程四维进度矩阵            |
| 文章是否已发布             | 文章 frontmatter 的 `publish.status` |

不要在文章中手工编造命令结果、性能数据或已实现功能。代码事实必须能追溯到测试、证据记录和 Git 引用。

## 每个单元的闭环

```text
确定学习问题
  → 在 ai-exp 做最小实验（需要时）
  → 在 OpsPilot 实现并测试
  → 在 docs/evidence 保存运行证据
  → 在 notebook 写成出版级文章
  → 审校并发布
  → 更新课程矩阵与项目里程碑
```

## 文章引用代码的规则

- 草稿阶段引用学习单元 ID 和相对代码路径。
- 里程碑完成后引用 Git tag，例如 `v0.1.0`。
- 文章中的关键代码可以节选，但完整实现以仓库为准。
- 代码演进后不静默重写历史文章；需要修正时增加勘误或引用补丁版本。
- 密钥、真实日志、个人数据和未脱敏事故信息不得进入证据或文章。
